# SnapGrab Pro — Media Engine

محرك خلفي اختياري لـ SnapGrab يستخدم `yt-dlp` بدل الاعتماد على روابط التحميل المباشرة وحدها. يدعم المواقع التي يتوفر لها **مستخرج معروف** داخل yt-dlp؛ القائمة كبيرة، لكنها ليست ضمانًا بأن كل منصة أو كل رابط سيعمل دائمًا.

## ماذا يضيف؟

- استخراج بيانات عامة مثل العنوان والقناة والصورة المصغرة والمدة.
- مهام تنزيل من جهة الخادم مع حالة وتقدم فعليين.
- فيديو MP4 أو WebM بالجودات التي يوفرها المصدر، مع عرض الصيغ الفعلية وأحجامها الدقيقة أو التقديرية، ومخرجات صوتية MP3 وM4A وAAC وFLAC وOPUS وOGG/Vorbis وWAV.
- دعم روابط Pinterest الكاملة، ومعالجة آمنة مختصرة لروابط `pin.it` التي تتحول إلى Pin عام؛ يقتصر مسار إعادة التوجيه على نطاقات Pinterest العامة المعروفة ولا يستخدم مستخرج الروابط العام.
- اختبارات وحدات محلية لسياسة الرابط واختيار الصيغة (لا تُنزّل أي وسائط).
- تحديد عدد المهام المتزامنة وحجم الملف والمدة ومعدل الطلبات.
- رفض قوائم التشغيل والرابط غير المدعوم بواسطة مستخرج مخصص، مع تعطيل المستخرج العام لتقليل مخاطر SSRF.
- حذف الملفات المؤقتة تلقائيًا بعد تنزيلها أو انتهاء صلاحية المهمة.

## تشغيل محلي على Windows

1. ثبّت Python 3.10+، وNode.js 22+، وFFmpeg وأضف `node` و`ffmpeg` إلى `PATH`.
2. افتح مجلد `media-engine` وشغّل `start_windows.bat`.
3. سيعمل المحرك على `http://127.0.0.1:8081`.
4. في ملف `.env.local` الموجود في جذر SnapGrab أضف: `MEDIA_ENGINE_URL=http://127.0.0.1:8081`.
5. شغّل SnapGrab باستخدام `npm run dev` وافتح `http://127.0.0.1:3000`. الاتصال المباشر بالـloopback يعمل محليًا دون مفتاح.
6. لتكامل إضافة Chrome، انسخ `.env.example` إلى `.env` في مجلد `media-engine`، ثم اضبط `MEDIA_ENGINE_ALLOW_CHROME_EXTENSIONS=true` وأعد تشغيل المحرك. في نافذة الإضافة أدخل `http://127.0.0.1:8081` واضغط «حفظ وفحص».
7. في نافذة طرفية أخرى، يمكن تشغيل اختبارات المحرك بعد تثبيت المتطلبات: `python -m unittest discover -s tests -v` (بعد تثبيت `requirements.txt`؛ تعتمد الاختبارات على حزمة yt-dlp المستوردة من المحرك).

## Docker / استضافة منفصلة

ابنِ الصورة من هذا المجلد وحده: `docker build -t snapgrab-media-engine .`، ثم انشر الحاوية على استضافة تدعم FastAPI وتخزينًا مؤقتًا مناسبًا. قبل إتاحتها للإنترنت، ولّد سرًا عشوائيًا قويًا (32 حرفًا أو أكثر) واضبط `ENGINE_API_KEY` عليه، واضبط `MAX_STORAGE_GB` و`MIN_FREE_DISK_MB` بحسب سعة القرص. أصبح المحرك يحجز مساحة تقديرية لكل مهمة بشكل متزامن لتقليل احتمال تجاوز الحصة أثناء تنزيلات متعددة. اترك منفذ المحرك خلف HTTPS ووسيلة proxy موثوقة إن أمكن.

في إعدادات مشروع Vercel اضبط `MEDIA_ENGINE_URL=https://your-engine.example` و`MEDIA_ENGINE_API_KEY` على **نفس قيمة** `ENGINE_API_KEY`. لا تضع السر في الواجهة أو الإضافة. يستعمل Vercel المفتاح للطلبات التي تحمل JSON فقط، ثم يعطي المتصفح رابطًا موقعًا لمدة 8 دقائق للتنزيل المباشر من محرك الوسائط. ملفات الفيديو لا تمر عبر Vercel Functions.

> عند عدم ضبط `ENGINE_API_KEY` لا يسمح المحرك بالوصول إلا من loopback، لذلك لا تفتح المنفذ علنًا بلا مفتاح. حدود المعدل الحالية داخل الذاكرة لكل نسخة؛ عند التوسع لعدة نسخ تحتاج محدد معدل مشترك. استخدمه لتنزيل ما تملكه أو ما لديك إذن واضح لتنزيله فقط. لا يمرّر المحرك ملفات تعريف الارتباط ولا يحاول تجاوز DRM أو تسجيل الدخول أو القيود الخاصة أو التحقق العمري.

## متغيرات اختيارية

- `PORT` — منفذ الاستماع (8081 افتراضيًا).
- `ENGINE_API_KEY` — مفتاح قوي مطلوب للوصول عن بُعد؛ يجب أن يطابق `MEDIA_ENGINE_API_KEY` في إعدادات Vercel. عند تركه فارغًا، يُسمح فقط بطلبات loopback المحلية.
- `MAX_STORAGE_GB` — حد التخزين المؤقت الإجمالي (8GB افتراضيًا).
- `TRUSTED_PROXY_CIDRS` — شبكات البروكسي الموثوقة التي يُسمح فقط لها بإرسال `X-Forwarded-For`؛ اتركه فارغًا إن لم تكن تدير هذه الشبكات بنفسك.
- `MIN_FREE_DISK_MB` — الحد الأدنى للمساحة الحرة الواجب الحفاظ عليها (256MB افتراضيًا).
- `MEDIA_ENGINE_ALLOWED_ORIGINS` — قائمة أصول الواجهة مفصولة بفواصل.
- `MEDIA_ENGINE_ALLOW_CHROME_EXTENSIONS` — الافتراضي `false`. إذا شُغّل `true`، يسمح للمحركات بالطلبات من أصل إضافة Chrome؛ فعّله فقط على محرك تملكه أو تثق به، ولا تستخدمه على خدمة عامة/مشتركة من دون مصادقة إضافية.
- `MAX_ACTIVE_JOBS` — أقصى عدد من المهام النشطة (3 افتراضيًا).
- `DOWNLOAD_WORKERS` — عدد عمال التنزيل (2 افتراضيًا، والحد الأعلى 4).
- `MAX_DURATION_SECONDS` — أقصى مدة بالثواني (10800 افتراضيًا).
- `MAX_FILE_MB` — حد الملف (1024MB افتراضيًا).
- `JOB_TTL_SECONDS` — مدة الاحتفاظ بحالة المهمة (3600 ثانية افتراضيًا).
- `RATE_LIMIT_PER_MINUTE` — عدد طلبات معلومات/إنشاء المهام في الدقيقة لكل عنوان عميل ظاهر للخادم (24 افتراضيًا). تحديث حالة المهمة يسمح بمعدل أعلى لأن الواجهة تراقب التقدم دوريًا.

## ملاحظات YouTube

الإصدارات الحديثة من yt-dlp تعتمد على `yt-dlp-ejs` ومحرك JavaScript حديث، ولهذا يستخدم المشروع `yt-dlp[default]` وNode.js 22. يمكن أن تتغير قيود YouTube أو تتطلب بعض الصيغ رمز PO Token؛ عندها يعرض المحرك خطأ بدل محاولة تخطي القيود.


### اختبار سياسات التخزين وعناوين العملاء دون تبعيات المحرك

```bash
cd media-engine
python -m unittest discover -s tests -p test_runtime_policy.py -v
```

هذه الاختبارات مستقلة عن `yt-dlp` وFastAPI. الاختبار الكامل عبر `npm run test:python` يحتاج تثبيت كل ما في `requirements.txt`.
